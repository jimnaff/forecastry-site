# forecastry-site

One-page website for Forecastry Analytics LLC.

- Live (after go-live): https://forecastryanalytics.com
- Until then: https://jimnaff.github.io/forecastry-site/

Plain HTML and CSS. No JavaScript, no framework, no build step.

## What's here

| Path | What it is |
|---|---|
| `index.html` | The page. All the text lives here. |
| `css/styles.css` | Colors, spacing and layout. Colors are custom properties at the top. |
| `favicon.svg` | Browser tab icon. Generated by `tools/make-assets.py`. |
| `images/jim-naff.jpg` | Original headshot. Source only; not published. |
| `images/jim-naff-300.jpg`, `images/jim-naff-600.jpg` | Resized headshots the page uses. Generated. |
| `images/og.png` | Social preview card (LinkedIn, Slack, etc.). Generated. |
| `robots.txt`, `sitemap.xml`, `CNAME` | Search engine files and the custom domain name. |
| `tools/` | Asset script, staging script, wording check, screenshot script. Not published. |
| `docs/screenshots/` | Phone and desktop screenshots of the page. Generated. Not published. |
| `.github/workflows/site.yml` | Checks every pull request; deploys on push to `main`. |
| `CLAUDE.md`, `.claude/` | Instructions for Claude Code, including the `/wording-check` command. |

Only these are published: `index.html`, `favicon.svg`, `robots.txt`, `sitemap.xml`,
`CNAME`, `css/`, and `images/` (minus the original headshot). `npm run stage` copies
them into `_site/`, and the checks and the deploy both use `_site/`.

## Edit the text

Open `index.html` and change the words between the tags. Keep `&amp;` for "&"
(for example `FP&amp;A`). Each section has an `id` (`services`, `about`, `tools`,
`contact`) that the menu links to; leave those alone.

The page title and description are in the `<head>` at the top, along with the
Open Graph tags that control the link preview.

Before committing, run `/wording-check` in Claude Code, or at least `npm run check`.

## Regenerate the images

Needs Python 3 with Pillow. On this machine use Python 3.12 (`py -3.12`), which has
Pillow installed.

```
py -3.12 -m pip install -r tools/requirements.txt
py -3.12 tools/make-assets.py
```

This rewrites `favicon.svg`, `images/og.png` and the two headshot sizes. The
headshot crop and the social-card text are constants at the top of the script.

## Run the checks

Needs Node 22 (22.22 or newer matches what the tools ask for) and Google Chrome.

```
npm ci
npm run check
```

`npm run check` stages the site, then runs html-validate, the wording check,
pa11y-ci (WCAG2AA, desktop and phone widths) and Lighthouse CI (mobile; performance,
accessibility, best practices and SEO must each score 0.9 or more).

Links are checked with [lychee](https://github.com/lycheeverse/lychee), which is a
separate program:

```
lychee --config lychee.toml _site/index.html
```

Run `npm run stage` first. LinkedIn links are skipped because LinkedIn blocks
link checkers.

## Update the screenshots

Run `npm run screenshots` after `npm ci`. It stages the site and writes
`docs/screenshots/phone.png` (375px) and `docs/screenshots/desktop.png` (1280px),
and fails if the page scrolls sideways at either width.

## How deploys work

1. Work on a branch and open a pull request. GitHub Actions runs every check above.
2. Merge when the checks are green.
3. The push to `main` runs the checks again, then deploys `_site/` to GitHub Pages.
   It takes a minute or two.

Pages is set to deploy from GitHub Actions (repo Settings → Pages → Source).

## Go live on the domain

These steps are for Jim. Nothing in this repo changes DNS or email.

### 1. Before you touch DNS

- In Namecheap, open **Domain List → forecastryanalytics.com → Advanced DNS** and
  take a screenshot of every record. That is your undo.
- Keep the nameservers on **Namecheap BasicDNS**.
- **Do not change or delete these.** They run your email (Namecheap Private Email):
  - MX records: `mx1.privateemail.com` and `mx2.privateemail.com`
  - The SPF TXT record on `@` (starts with `v=spf1`)
  - The DKIM TXT record on `default._domainkey`
  - The DMARC TXT record on `_dmarc`, if there is one

### 2. Recommended: verify the domain with GitHub

This stops anyone else from claiming the domain on GitHub Pages.

1. GitHub → your profile picture → **Settings → Pages** (account settings, not the
   repo) → **Add a domain** → `forecastryanalytics.com`.
2. GitHub shows a TXT record. Add it in Namecheap Advanced DNS:
   - Type `TXT`, Host `_github-pages-challenge-jimnaff`, Value as shown by GitHub.
3. Wait a few minutes, then click **Verify**.

### 3. Point the domain at GitHub Pages

In Namecheap Advanced DNS:

1. Delete the parking records for `@` and `www` (a URL Redirect record and/or a
   CNAME to `parkingpage.namecheap.com`).
2. Add these. TTL **Automatic**.

| Type | Host | Value |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `jimnaff.github.io.` |

Optional, for IPv6:

| Type | Host | Value |
|---|---|---|
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |

### 4. Tell GitHub about the domain

1. Repo **Settings → Pages → Custom domain**: enter `forecastryanalytics.com` and save.
2. Wait for the DNS check to pass. This can take from a few minutes to an hour.
3. Tick **Enforce HTTPS** once GitHub has issued the certificate (the box becomes
   clickable).

After this, https://jimnaff.github.io/forecastry-site/ redirects to the domain.
With Actions deploys, GitHub uses this setting, not the `CNAME` file. The file is
kept as a record of the intended domain.

### 5. Check the site

```
nslookup forecastryanalytics.com
nslookup www.forecastryanalytics.com
```

- The apex should list the four `185.199.x.153` addresses.
- `www` should be an alias of `jimnaff.github.io`.
- https://forecastryanalytics.com shows the site with a padlock.
- https://www.forecastryanalytics.com redirects to https://forecastryanalytics.com.

Then remove the `forecastryanalytics.com` line from `exclude` in `lychee.toml`, so
the link check covers the live domain.

### 6. Check email still works

1. `nslookup -type=mx forecastryanalytics.com` still shows `privateemail.com`.
2. Send a message from Gmail to jim@forecastryanalytics.com. It arrives.
3. Send a message from jim@forecastryanalytics.com to Gmail. It arrives and is not
   in spam. In Gmail, open it → **⋮ → Show original**: SPF and DKIM both say PASS.
4. On the live site, click **Get in touch**. It opens a new email to
   jim@forecastryanalytics.com.

If anything in email breaks, compare Advanced DNS with your screenshot from step 1
and put back what changed.
